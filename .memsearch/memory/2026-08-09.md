- Claude traced the Nuvio sync code path (497-line core/nuvio.py, 6871-line backend/routers/sync.py) and identified that Nuvio uses IMDb ids while scrob's database is TMDB-keyed, requiring TMDB `/find` calls for resolution.
- Claude created and ran benchmarks (bench_pool.py, repro_sync.py) showing: Nuvio pull itself is only 0.38s for 2,000 items; TMDB resolution dominates at ~48s with current config (new client per request, concurrency=5), but would drop to 4s with pooled client and higher concurrency.
- Claude discovered root cause: watched-only users re-resolve 2,000 IMDb ids every sync (2,000 TMDB calls), while collection-sync users resolve zero—because the IMDb→TMDB cache persists only via `CollectionFile` rows, which are written only when `sync_collection=ON`.
- Claude completed Phase 1 investigation with concrete evidence and identified secondary issues: no connection pooling in tmdb.py, global `_sync_semaphore` limiting all syncs to sequential execution, conservative `TMDB_CONCURRENCY=5`, and redundant re-auth on each operation.
